## 东京 DC39v2 线路怎么样：延迟、路由和速度参考

国内三网到 DC39v2 的平均延迟在 77ms 上下，去程三网直连，回程以移动 CMI 为主。要说明一点：这些数据出自 The Tokyo Plan v1 机型的公开测评，v2 和它在同一个机房、同一条线路上，硬件升级不会改变网络路径，所以下面的数字可以直接当 v2 的参考。

| 线路 | 平均延迟 | 最快节点 |
| --- | --- | --- |
| 电信 | 75.7ms | 上海（天翼云 CN2）36.4ms |
| 联通 | 89.7ms | 浙江杭州 32.5ms |
| 移动 | 77.1ms | 浙江金华 46.1ms |
| 全国全部节点 | 77.2ms | 上海（阿里云）32.4ms |

路由细节比平均值更有参考价值。去程方向，电信走 CN2、联通走 AS4837、移动走 AS9808；回程以移动 CMI 为主，但测评里提到部分情况下回程可能绕行电信 163 骨干。电信用户在个别路径上会遇到普通 163 线路的表现，晚高峰波动可能比纯 CMI 明显一点，这点要有预期。

速度方面，平峰时段苏州电信 5G 环境实测上传 2.2Gbps、下载 1.1Gbps。5Gbps 端口没有跑满，但这个成绩对绝大多数用途已经足够宽裕。硬件本身也不拖后腿：AMD EPYC（Genoa）主频约 2.45GHz，单核 Sysbench 跑出 3679 分；4K 随机读写 IOPS 接近 7 万，1M 块顺序读 9.8GB/s、写 10.46GB/s。v1 单核就这水平，v2 翻到 2 核，多线程吞吐只会更好。另外测评里 NAT 类型显示 Full Cone，对联机游戏比较友好。

已公布的测试 IP 是 74.82.195.163，下单前可以先 ping 或者 traceroute 一遍，看看自己宽带的实际路由。
